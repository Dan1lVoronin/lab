== Отчёты

== 1. Что такое операционная система (ОС)

Операционная система (ОС) — это комплекс программ, обеспечивающих управление аппаратными средствами компьютера и выполнение прикладных программ. ОС организует взаимодействие пользователя с системой, распределение ресурсов, выполнение задач и управление файлами.

== 2. Что такое операционная система реального времени (ОСРВ)

ОСРВ (Операционная система реального времени) — это разновидность ОС, предназначенная для выполнения задач в строго заданное время. ОСРВ часто используется во встраиваемых системах, где критично соблюдение временных ограничений (например, в системах управления автомобилем, медицинских приборах).

== 3. Виды ОСРВ

- Жёсткая ОСРВ — соблюдение временных ограничений обязательно, иначе возможны фатальные ошибки.
- Мягкая ОСРВ — превышение времени возможно, но нежелательно.
- Однозадачные и многозадачные ОСРВ — в зависимости от количества одновременно выполняемых задач.

== 4. Многозадачность

Многозадачность — способность системы выполнять несколько задач одновременно. В многозадачных ОСРВ каждая задача получает часть процессорного времени, планировщик решает, какая задача и когда будет выполняться.

== 5. Планировщик задач

Планировщик задач — компонент ОСРВ, который решает, какая задача должна быть активной в данный момент.

Типы планировщиков:

- *Приоритетный* — задачи с более высоким приоритетом запускаются раньше.
- *Циклический (Round-Robin)* — задачи получают процессор по очереди.
- *Кооперативный* — задача сама должна «уступить» управление.
- *Вытесняющий* — ОС может остановить задачу и включить другую с более высоким приоритетом.

== 6. FreeRTOS

FreeRTOS — это популярная реализация ОСРВ с открытым исходным кодом, ориентированная на микроконтроллеры.
 FreeRTOS поддерживает:

- Задачи (tasks)
- Очереди (queues)
- Мьютексы (mutexes)
- Таймеры
- Семафоры

== 7. Межзадачное взаимодействие

Взаимодействие между задачами в ОСРВ необходимо для синхронизации работы и обмена данными. 

Основные способы:

- *Очереди* — одна задача кладёт данные в очередь, другая — забирает.
- *Семафоры* — используются как флажки: задача ждёт, пока другой не даст «разрешение».
- *Мьютексы* — нужны, чтобы защитить общий ресурс от одновременного доступа.
- *События* — позволяют одной задаче дать сигнал другой.

== 8. Типы межзадачного взаимодействия

- *Передача данных (producer-consumer)* — одна задача что-то производит, другая это обрабатывает. Например, одна читает с датчика, другая — сохраняет данные.
- *Синхронизация* — чтобы к ресурсу (например, к общей переменной) одновременно не обратились две задачи, используется мьютекс.
- *Сигнализация событий* — одна задача посылает сигнал, другая реагирует (например, завершение чтения файла).
- *Таймерные сигналы* — задача запускается, когда сработает таймер.

== 9. Задачи

Задача (или поток) — это отдельный блок кода, который выполняется независимо от других. Каждая задача:

- выполняет свою функцию;
- имеет свой стек (память для работы);
- получает приоритет, чтобы ОС знала, насколько она важна.

В FreeRTOS задачи создаются через `xTaskCreate()`. Там указывается, какую функцию выполнять, сколько памяти выделить, и какой будет приоритет.

Пример:
[source,cpp]
----
xTaskCreate(TaskReadSensor, "Sensor", 100, NULL, 2, NULL);
xTaskCreate(TaskDisplay, "Display", 100, NULL, 1, NULL);
----

== 10. Запрет планировщика и прерываний

Иногда нужно, чтобы никто не мешал задаче выполнить важную часть кода — это называется критическая секция. Чтобы её защитить, можно временно остановить планировщик или запретить прерывания.

- `vTaskSuspendAll()` — временно блокирует переключение задач.
- `xTaskResumeAll()` — возобновляет планировщик.
- `taskENTER_CRITICAL()` и `taskEXIT_CRITICAL()` — отключают прерывания, чтобы текущая задача точно всё выполнила.

Пример:
[source,cpp]
----
taskENTER_CRITICAL();
// изменение общей переменной
taskEXIT_CRITICAL();
----

== 11. Мьютексы

Мьютекс (mutual exclusion) — это способ не дать двум задачам одновременно менять один и тот же ресурс. Только одна задача может «захватить» мьютекс. Пока она его не отпустит — другие будут ждать.

В FreeRTOS мьютексы реализованы через бинарные семафоры. Также используется механизм приоритетного наследования, чтобы избежать ситуаций, когда важная задача долго ждёт менее важную.

Пример:
[source,cpp]
----
if (xSemaphoreTake(mutex, 100)) {
    // критическая секция
    xSemaphoreGive(mutex);
}
----

== 12. Дедлок (взаимная блокировка)

Дедлок — это ситуация, при которой несколько задач блокируют друг друга, пытаясь получить доступ к уже занятым ресурсам. Например, одна задача удерживает мьютекс A и ждёт мьютекс B, а другая — наоборот. В таком случае выполнение останавливается, и ни одна из задач не может продолжить работу.

В рассматриваемом проекте использовалась операционная система реального времени (RTOS) с обёрткой `OsWrapper`, которая упрощает работу с системными мьютексами. Вместо использования прямых вызовов RTOS, был применён класс `Mutex`, инкапсулирующий всю необходимую логику.

Пример использования мьютекса через обёртку:

[source,cpp]
----
OsWrapper::Mutex mutex;

if (mutex.Lock(100)) {
    // Критическая секция
    mutex.UnLock();
} else {
    // Захват не удался — выходим
}
----

Класс `Mutex` автоматически создаёт и удаляет мьютекс через функции `RtosWrapper`. Метод `Lock()` позволяет попытаться захватить мьютекс с тайм-аутом (например, 100 мс), что предотвращает зависание задачи при долгом ожидании ресурса. После завершения работы в критической секции вызывается `UnLock()`.

Такой подход делает код более читаемым, безопасным и легко переносимым на другие RTOS. Вся логика управления мьютексами сосредоточена в одном месте.

=== Меры по предотвращению дедлоков

В проекте были применены следующие приёмы, позволяющие исключить появление взаимных блокировок:

- *Тайм-аут при захвате мьютекса*  
  Все захваты мьютексов выполнялись с ограничением по времени, например `Lock(100)`. Это предотвращает бесконечное ожидание ресурса.

- *Глобальный порядок захвата ресурсов*  
  Хотя проект не содержит задач, одновременно работающих с несколькими мьютексами, архитектура предполагает, что в случае необходимости захват будет производиться в фиксированном порядке. Это позволяет избежать циклической блокировки между задачами.

- *Избегание вложенных блокировок*  
  Код построен так, что внутри уже захваченной критической секции не выполняются повторные вызовы `Lock()`. Это делает структуру программы проще и снижает вероятность логических ошибок.



Применение обёртки над мьютексами сделало работу с синхронизацией более безопасной и удобной. Использование тайм-аутов, соблюдение архитектурных ограничений и упрощённая структура кода позволили избежать возникновения дедлоков при выполнении проекта.

=== Почему это было сделано через операционную систему

Для реализации многозадачности и безопасного доступа к общим ресурсам в проекте использовалась операционная система реального времени (RTOS). Она предоставляет встроенные механизмы синхронизации, такие как мьютексы, очереди, семафоры, и умеет управлять задачами по приоритету.

Работать напрямую с низкоуровневыми функциями RTOS было бы неудобно, поэтому была реализована собственная обёртка `OsWrapper`. Она делает использование мьютексов и других механизмов проще и безопаснее — вся логика захвата, освобождения, тайм-аутов и удаления мьютекса спрятана внутрь класса.

Такой подход позволил:
- централизовать все вызовы к мьютексам;
- задать единые правила их использования;
- упростить отладку и избежать ошибок, связанных с прямым управлением ресурсами.

Использование операционной системы позволило легко запускать несколько задач параллельно, распределять приоритеты и обрабатывать всё по времени. Это особенно важно для встраиваемых систем, где задержки недопустимы.
