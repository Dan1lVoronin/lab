== Цель

Целью данной работы является изучение этапов превращения исходного кода в исполняемый файл для микроконтроллера.

== Введение

Преобразование программы, написанной на языке *C++*, в исполняемый файл для микроконтроллера включает два ключевых этапа: компиляцию и последующую линковку.

== Трансляция кода в объектный файл

За этот этап отвечает *компилятор*, который обрабатывает исходный код и формирует на его основе *объектный файл*.

После трансляции можно получить два типа файлов:

* *Объектные файлы*, содержащие машинный код;
* *Файлы библиотеки*, которые можно использовать в других проектах.

== Компоновка кода в исполняемый файл

На этом этапе *линковщик* объединяет все необходимые файлы и формирует *исполнимый образ* программы.

На входе линковщика могут быть:

* *Внешние библиотеки*, добавляемые в проект;
* *Объектные файлы*, полученные на этапе трансляции;
* *Стандартные библиотеки C++*;
* *Конфигурационный файл*, который определяет размещение кода и данных в памяти микроконтроллера.

В результате работы линковщика формируется *исполняемый файл*, который затем можно загрузить в память микроконтроллера.

== Запуск и отладка

После компоновки IAR создает *файл в формате ELF*, который можно использовать для:

* *Загрузки в систему отладки* (например, IAR-CSPY или GDB);
* *Записи в ПЗУ микроконтроллера* с помощью программатора.

== Запуск функции main() в микроконтроллере

Загрузка исполняемого файла в память микроконтроллера запускает цепочку инициализаций, предшествующих вызову функции `main()`.

=== Аппаратный сброс

При подаче питания или по сигналу сброса (Reset) микроконтроллер начинает выполнение программы с определённого адреса, обычно указанного в векторе сброса.

=== Переход к Reset Handler

В таблице прерываний указан адрес функции Reset Handler — именно она первой начинает выполняться после сброса.

=== Инициализация стека и переменных

Первым шагом является инициализация *стека* и *глобальных переменных*. Также инициализируются статические переменные.

=== Копирование данных из ПЗУ в ОЗУ

Данные из *ПЗУ* копируются только если надо проинициализировать глобальные переменные. Либо если программист сам решил, что ПО должно запускаться из *ОЗУ*. Но в нашем микроконтроллере, работа из *ОЗУ* и *ПЗУ* по скорости одинаковая, так как частота работы не высокая.

=== Обнуление сегмента .bss

Все неинициализированные глобальные и статические переменные обнуляются, чтобы они не содержали случайных данных.

Глобальные и статические переменные, у которых нет начального значения, обнуляются, но это происходит не само по себе — такой код либо пишет программист, либо его автоматически добавляет компилятор. Без этого переменные могли бы содержать случайные данные.

=== Инициализация периферийных устройств

Происходит настройка периферийных устройств (таймеры, GPIO, интерфейсы и т.д.), как правило, с помощью библиотек и драйверов.

=== Передача управления в main()

После всех подготовительных этапов управление передаётся в main() и начинается выполнение программы.

== Объяснение работы статической переменной в функции

Пример кода:

[source,cpp]
----
#include <iostream>

int Increment(int value)
{
    static int result = value;
    result++;
    return result;
}

int main()
{
    auto result = Increment(10);
    std::cout << "result == " << result << std::endl; // 11

    result = Increment(12);
    std::cout << "result == " << result << std::endl; // 12
}
----

=== Что такое статическая переменная?

`static` переменная в функции сохраняет своё значение между вызовами. Она инициализируется один раз — при первом вызове — и сохраняет состояние, даже после выхода из функции.

=== Пояснение к примеру

* Первый вызов `Increment(10)` инициализирует `result = 10`, затем увеличивает до 11.
* Второй вызов `Increment(12)` не меняет инициализацию — `result` уже 11, увеличивается до 12.

=== Итог

Результат работы программы:

* Первый вывод: `result == 11`;
* Второй вывод: `result == 12`.

== Почему код пишут самые низкоквалифицированные инженеры?

Я считаю, что код пишут самые низкоквалифицированные инженеры, потому что в наше время есть большое количество нейросетей, которые неплохо умеют это делать. Если правильно поставить задачу нейронке (написать хороший промпт), тогда она выдаст неплохой ответ, который по ходу диалога можно довести до ума. Задача разработчика - знать, что от него требуют, как должен выглядеть продукт, и написать правильный и понятный код, чтобы другие программисты смогли работать с ним.
